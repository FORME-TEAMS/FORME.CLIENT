# Сборка и запуск ForMe.World

## Что находится в репозитории

Это исходники клиента. Для запуска мира отдельно нужны серверные службы ForMe.World и регион. Компиляция клиента не создаёт сервер, базу данных или учётную запись.

Единая точка входа — `scripts/forme_client.py`. Она выбирает профиль платформы, получает закреплённый набор публичных переменных сборки и сохраняет серверный режим доступа. Закрытые библиотеки, голосовое общение и автоматическая публикация в этот профиль не включаются.

## Доступ и получение кода

Установите Git и GitHub CLI. Учётная запись должна иметь доступ к этому закрытому репозиторию. Выполните:

```sh
gh auth login
gh auth setup-git
gh repo clone FORME-TEAMS/FORME.CLIENT
cd FORME.CLIENT
git switch main
git rev-parse HEAD
```

Сохраните commit: это точная версия собираемых исходников. Не добавляйте токены в URL клонирования или в файлы проекта.

## Выбор инструкции

- [macOS](building_macos.md): Xcode 16.4, универсальное приложение для Intel и Apple Silicon.
- [Windows](building_windows.md): Visual Studio 2022, x64.
- [Linux](building_linux.md): среда x86_64, проверяемая отдельной полной сборкой.

Ориентируйтесь на 16 ГБ RAM и не менее 64 ГБ свободного места. Первая компиляция скачивает зависимости и занимает заметно больше времени, чем повторная. При нехватке памяти используйте `build --jobs 1`.

## Адрес сервера

Адрес по умолчанию — `http://185.173.93.200:8002/`. Это URL служб входа; он должен быть доступен с компьютера игрока. Для своей установки укажите её URL, например:

```sh
python3 scripts/forme_client.py configure --grid-url https://grid.example.org:8002/
```

В Windows вместо `python3` используйте `python` из активированного окружения. Адрес в примере нужно заменить реальным. В URL нельзя помещать имя пользователя, пароль, query или fragment. После изменения адреса повторите configure и build. `127.0.0.1` подходит только когда клиент и службы работают на одном компьютере.

## Команды

| Команда | Назначение |
| --- | --- |
| `check` | Проверки исходников, типов, интерфейса, ограничений и упаковки |
| `configure` | Проверки, получение переменных и настройка зависимостей/сборки |
| `build --jobs 3` | Компиляция подготовленного проекта |
| `bundle` | Проверка, локальная подпись и ZIP-архив приложения macOS |
| `run` | Запуск собранного приложения |

На любой ошибке остановитесь и прочитайте первое сообщение об ошибке. Не переходите к запуску после неуспешного configure или build. Отсутствующий артефакт не заменяется архивом исходников.

## Что проверять после запуска

1. Вход в свой аккаунт, профиль и баланс, открытие региональной карты.
2. Инвентарь и примерочную, сохранённые образы и действия с предметами.
3. Полный чат, личные диалоги, группы и уведомления.
4. Переход A → B → A, неуспешный переход, повторный вход; старые ответы не должны восстанавливать прежний контекст.
5. Музыку/прямой поток региона и отсутствие настроек голосового общения.
6. Создание и редактирование под разрешённой ролью и отказ обычному пользователю.

Это список приёмки, а не заявление, что все сценарии уже подтверждены для нового репозитория.

## Диагностика и обновление

В отчёт приложите commit, платформу, версии Python/CMake/компилятора, команду и первые сообщения об ошибке. Секреты удалите. Для обновления сначала сохраните свои изменения, затем выполните `git pull --ff-only`, повторите configure и build.

Набор переменных закреплён commit в сборочном скрипте. Рабочие каталоги `build-variables`, `.venv`, `build-*`, `.autobuild-installables` и `dist` не коммитятся. Не удаляйте собственные каталоги или изменения ради очистки; для полностью чистого воспроизведения используйте новое клонирование.

Сохранность лицензий и уведомлений обязательна и для собранных приложений. Закрытый репозиторий не освобождает от условий лицензий при передаче приложения другим лицам.
